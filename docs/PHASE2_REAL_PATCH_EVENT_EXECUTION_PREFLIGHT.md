# Phase 2 real patch-event execution preflight

The independently accepted component inventory makes a national patch-event storage bound possible without guessing from a sample. The exact inputs are 1,384,027,417 loss cells, 303,530,909 finalized components, 528,596,703 inclusive-x runs, 12,199,309 aliases and 68,322,924,822 retained input bytes across 38 pairs.

The bounded exact method is recorded in [`data/phase2-real-patch-event-execution-preflight.json`](../data/phase2-real-patch-event-execution-preflight.json). Each pair receives a first pass that resolves every source component ID to its already-validated final root. A second pass emits fixed 20-byte run records and externally sorts bounded 1 GiB chunks by final root, row and x range. A bounded merge can then stream one component at a time into the existing `realDetectedChangeEvent` contract: sorted cells, one unsimplified 30 m polygon per cell, exact 0.09-hectare area, checksum-derived ID, source lineage and the approved versioned non-production method identity. Final names remain unavailable until a complete file is flushed, fsynced and atomically promoted to an unused name.

The storage envelope deliberately exceeds the expected encoding: 512 bytes per loss cell, 4,096 fixed bytes per event and 64 scratch bytes per run. The per-cell allowance covers both the decimal cell index and five closed coordinate pairs even at the opposite grid corners; focused tests serialize those extrema through the executable event contract. The scratch allowance covers both a 20-byte sortable run and a second per-component run spool with additional margin. Including the retained component inputs, the resulting upper bound is 2,054,037,754,582 bytes, leaving 144,985,500,970 bytes below the approved 2 TiB cap.

Storage passing does not admit the national execution. Completion within 96 hours still requires a measured sustained rate of at least 4,005 cells, 879 events and 5,647,815 bounded output bytes per second. The next safe action is the recorded pilot: only pair 1984–1985, at most 10,000 finalized components, 64 MiB output, 2 GiB scratch and 1,800 seconds. Any limit leaves only a partial file. Until that pilot and its exact readback pass, `runtimePreflight.passes` and `nationalExecutionAdmitted` remain false. No real patch/event output, release, boundary intersection or production claim was created by this preflight.

The fail-closed pilot runner is implemented but has not been executed. It pins both approved 1984–1985 input hashes, selects the first 10,000 finalized components, resolves their aliases, and uses only 20-byte run records in a bounded 1 GiB memory-mapped sort chunk. The spool is sorted in place before output begins, so at most two whole-run copies coexist while compact output is written. Every compact event losslessly encodes the exact ascending `cellIndices` and one unsimplified 30 m polygon per cell; it also records the exact 0.09-hectare area, dates, evidence, lineage, method, coverage grade, stable event ID and `realDetectedChangeEvent` patch checksum. Tests pin the checksum at both grid extremes and across rows against test-owned Node-contract digests.

The runner enforces the 64 MiB output, 2 GiB scratch, 1,800-second, 8-vCPU and 16 GiB limits. A parent watchdog owns the entire child lifetime, kills the child process group on the wall-time boundary, polls RSS, and requires observed peak RSS, CPU time, average vCPU, affinity availability and single-thread environment telemetry. The child also applies the CPU rlimit, CPU affinity and address-space rlimit where the host exposes those controls; on macOS, where Python exposes no CPU-affinity API and rejects the address-space rlimit, the record says so instead of inventing enforcement, while the single-thread environment, observed average-vCPU gate, peak-RSS self-readback and independent parent RSS watchdog remain mandatory. The supervisor opens the owner-only output parent once, passes that exact directory descriptor and the output basename across the fork, and releases the child through a post-fork gate only if the pathname still resolves to the same directory identity. The child never reopens the output parent pathname. Output and scratch names are resolved beneath that inherited descriptor; every file is created with `O_EXCL`, `O_NOFOLLOW`, mode 600 and checked device, inode, link-count and ctime state. Sorting, writing and readback stay bound to the opened descriptors. Publication uses a same-directory, no-copy hard link and proves that the final name references the verified partial inode; replacement and final-name races fail closed. The persisted telemetry reconciles writer and readback totals, body digest, payload digest, byte lengths and candidate file SHA, then a final attestation checksum-binds the telemetry. No real pilot output, release or production claim exists.
