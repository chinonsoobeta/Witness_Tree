# Plan gap matrix

**Current assessment:** 2026-08-31 (Pacific), with the owner's 2026-09-26 [phase scope decision](PHASE_SCOPE_DECISION_2026-09-26.md) applied to Phases 1, 2 and 7. This matrix reports literal Version 2.1 gate counts where Version 2.1 defines them. Version 2.1 expressly assigns no cumulative Phase 3 percentage; its Phase 3 row therefore reports evidence status rather than a maturity score. That prohibition is on inventing a cumulative percentage, not on counting the phase's five literal published exit criteria, which are now gated like every other phase by [`check:phase3-frontend-foundation-exit-status`](../scripts/check-phase3-frontend-foundation-exit-status.mjs). The two numbers answer different questions and must not be substituted for one another: 4 of 5 literal criteria passing is not Phase 3 being four fifths complete. A local control, contract, fixture, or technical preview is never evidence of production admission, external review, or launch.

**Technical preview warning:** the deployed site remains a technical preview. It includes bounded province-level map delivery and an independently retrieved immutable CSV and GeoPackage release. It is not a beta invitation or evidence that any general production source, wildfire feed, account service, or alert sender is live.

## Counting rule

Each fraction above is an unweighted count of the literal gates for that phase. Every phase whose record carries one states its own counting boundary, and the contract refuses a record that will not say what its number is not. The Phase 3 evidence row stays explicitly non-numeric, not an overall-project percentage and not a weighted estimate. Do not average the rows or upgrade a phase because code, documentation, fixtures, a checksum, or a local test exists. A gate closes only with its specified current evidence; production and launch additionally require admitted real data, operational evidence, and all applicable approvals.
