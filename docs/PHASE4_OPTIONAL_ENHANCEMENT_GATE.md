# Phase 4 optional-enhancement gate

`lib/phase4/optional-enhancement.ts` is the local admission boundary for a BC or Québec optional enhancement. It returns `available` only when all three conditions are true: reuse rights are verified, the source evidence is admitted, and an admitted enhancement-coverage geometry contains the queried point and year with the `enhanced-local-records` grade.

Every other case returns a bilingual `Unknown` without a numeric value. An unavailable result may have no boundary edition because no admitted local detail exists; a boundary edition is mandatory only before the gate can return `available`. It does not turn missing optional coverage into zero, and it does not allow a national-baseline or local-context grade to impersonate enhanced coverage. The gate is deliberately before event processing. Existing executable policies then retain their separate jobs: FTA lifecycle normalization, matching tolerances, precedence, tenure and subtype validation.

The machine-checked formal state is [`data/phase4-exit-status.json`](../data/phase4-exit-status.json): **3/4 (75%)**. Its four criteria are exactly the plan’s lifecycle, Québec-north-of-52 coverage, published match/non-match reporting, and subtype rules. The [methods page](../app/en/methods/page.tsx) now explicitly publishes the honest unavailable state for the match rate, non-match rate, and non-match-reason distribution. The reporting criterion remains open: it requires numeric results from an admitted, versioned provincial processing run, not a placeholder or fixture. Rights/admission remains blocked. The owner decided not to pursue the separate BC/QC human-review checkpoint; because no review or reviewer sign-off occurred, that checkpoint also remains blocked.

`data/phase4-provincial-matching-preflight.json` and `lib/phase4/provincial-matching.ts` now provide the smallest executable reporting boundary. The preflight checksum-binds the staged Québec geometry/event evidence and Phase 2 evidence, but records null values because the Québec rows are not production-admitted, no event transformation is approved, and Phase 2 has no materialized change geometries to match. The reusable report function emits rates and a non-match-reason distribution only when all those conditions are explicitly true; it remains non-production even then.
